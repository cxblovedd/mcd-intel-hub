## 两个能力，一个数据底座

### 能力一：开抢情报

麦当劳的优惠信息散落在**三个互不相通的入口**：活动日历、麦麦省优惠券、积分商城。于是产生了这个真实场景：你看到「联名徽章 10:45 开售」，但**你不知道现在是10:09 还是 10:14**。

**麦麦情报站回答：下一个开抢窗口，还有多久。**

### 能力二：麦门人格

基于你的**真实历史订单**，从口味、作息、足迹、消费四个维度推导出一个属于你的麦门人格标签，生成可分享的画像海报。

```markdown
## 甜品判官
> 冰淇淋和麦旋风是你续命的理由

| 维度 | 人格标签 | 画像解读 |
|---|---|---|
| 作息节律 | **午餐党** | 午间补给站，稳定输出型选手 |
| 消费足迹 | **跨城游侠** | 足迹遍布 4 座城市，6 家门店 |
| 消费习惯 | **稳健型消费者** | 平均每单 ¥53，花钱花得明白 |

数据档案：8笔订单 · 8 个月 · 6 家门店 · 33 件餐品
```

*（以上为基于真实订单数据的实际运行结果）*

## 为什么能传播

情报是**时间稀缺信息**，人格是**社交货币**。

前者让人立刻转发给同事群（「10:45 开售，你还剩 5 小时」），后者让人主动晒朋友圈（「我是甜品判官，你是什么」）。两者共用同一套MCP 数据底座，不额外增加调用成本。

## 安装方法

### 前置条件

1. **申请麦当劳 MCP Token**
   前往 https://open.mcd.cn/mcp 登录并激活，复制生成的 Token。

2. **准备支持 Skill 的客户端**
   本 Skill 为标准 `SKILL.md` 格式，推荐 WorkBuddy，亦可适配其他兼容 Agent Skills 的客户端。

### 步骤一：配置 MCP 连接

编辑你的 MCP 客户端配置文件，参考本仓库的 `mcp-config.example.json`：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

> ⚠️ 请通过环境变量注入 Token，**切勿将真实 Token 提交到仓库**。

### 步骤二：安装 Skill

将本仓库克隆到你的技能目录：

```bash
git clone https://github.com/<your-account>/mcd-intel-hub.git
```

WorkBuddy 用户可将仓库置于技能目录后在「专家 · 技能 · 连接器」中启用。

### 步骤三：启用连接器

在客户端的连接器管理中启用 `mcd-mcp`，确认状态为「已连接」。

## 设计原则

**不编造数据。** 所有时间、价格、库存均来自 MCP 实时返回。接口未返回时明确标注「接口未返回」，绝不用推测值填充。

**写操作一律确认。** 领券、抽奖、兑换下单、派对下单，执行前必须展示内容并获得明确同意。

**过期的情报就是噪音。** 往期回顾中的开售时间会被自动识别并剔除——用户要的是未来窗口，不是三天前的活动。

**中立客观。** 只陈述数值与事实，不对产品作评价性、对比性表述。

## 开发与测试

```bash
# 情报解析器：使用内置示例数据验证
python3 scripts/intel_parser.py --demo

# 情报解析器：使用真实 MCP 数据生成简报
python3 scripts/intel_parser.py \
  --calendar calendar.txt \
  --mall mall.json \
  --now "2026-10-09 15:39"

# 人格画像：使用示例订单验证
python3 scripts/persona_builder.py --demo

# 人格画像：使用真实订单生成
python3 scripts/persona_builder.py \
  --orders orders.json \
  --points '{"availablePoint":"485.7","accumulativePoint":"2265.1"}'
```

两个脚本仅依赖 Python 3.8+ 标准库，无需安装额外依赖。

### 边界场景已验证

| 场景 | 表现 |
|---|---|
| 0 笔订单（全新用户） | 输出「麦门新客」，各维度标注「数据不足」，不崩溃 |
| 1 笔订单 | 能生成画像，标签可能偏主观但逻辑自洽 |
| 全部为取消订单 | 视为0 笔有效订单处理 |
| 全为积分兑换（实付 0 元） | 消费维度标记为「权益型消费者」 |
| 活动文案含已过期开售时间 | 自动识别并剔除，不误报为未来窗口 |
